# 思源规则提醒编写教程

思源插件负责连接核心、读取原生 callout 和转接推送。规则使用引擎共同的 `schemaVersion: 2` 声明，由 `@leolee9086/dsh-rule-engine` 解码、校验和执行。context-care 提供 Host 服务；思源插件不解释条件、动作、投递策略或旧版规则格式。

## 1. 创建原生 callout

在思源创建 callout，把类型标记设为 `[!DSH-REMINDER]`，内部放且只放一个 `dsh-rule` 围栏。围栏外正文是提醒模板。块数据库的 `type` 为 `callout`，`subtype` 为 `DSH-REMINDER`；普通引述块中写相同文字不会成为这个来源。

````markdown
> [!DSH-REMINDER] TypeScript 类型约定
>
> ```dsh-rule
> schemaVersion: 2
> id: typescript-no-any
> revision: 1
> on: [tool.succeeded]
> select:
>   view: original
>   roles: [tool]
>   blockTypes: [tool-result]
> event:
>   tool: read
>   arguments:
>     file_path:
>       regex: '\.tsx?$'
>       flags: i
> match: { kind: always }
> actions:
>   - id: model
>     kind: notify
>     stage: tool.succeeded
>     enabledDefault: true
>     delivery:
>       model: { once: surface }
> ```
>
> 禁止使用 `any`。类型暂不明确时使用 `unknown`，再缩小类型范围。
````

保存后等待索引与推送更新，成功读取 TypeScript 文件时，引擎在下一次自然模型请求前交付提醒。没有主动唤醒空闲会话的定时任务。围栏采用 YAML 1.2，也可使用 JSON；重复键和循环数据会产生来源诊断。

## 2. 身份、模板与字段

- `id` 为显式非空字符串；与思源块 ID 一起形成规则身份。核心 ID 隔离来源，移动文档不改变身份。
- `revision` 为正整数；`on` 声明阶段；每个动作的 `stage` 必须在 `on` 内。
- `select` 指定事实切面；工具事件通常使用 `original`、`tool`、`tool-result`。
- `event` 选择事件事实，`match` 是共同条件树，`actions` 是共同动作序列。
- 文档来源补充来源身份与标题。围栏外非空正文填入支持文本模板的核心动作；没有正文时保留动作的显式 `template`。
- `priority` 默认 0，较大的优先；`exclusiveGroup` 在互斥规则间选择赢家。同一规则的适用动作分别执行。

`format`、`when`、`effect`、`scope` 不属于这份共同声明。旧笔记需改写为 `event`、`match`、`actions[].delivery`、`recipient`；运行时不猜测或升级旧格式。

## 3. 正则、路径与嵌套条件

`event.arguments` 对指定顶层工具参数执行正则，缺失参数正常不匹配。单引号 YAML 正则中的反斜杠只写一次。Windows 路径可用 `[\/]` 同时接受两种分隔符：

```yaml
event:
  tool: read
  arguments:
    file_path:
      regex: '^D:[\/]dev[\/]my-project[\/].*\.js$'
      flags: i
```

数字、布尔值或嵌套参数放进 `match`，例如只允许 TypeScript 实现文件：

```yaml
match:
  kind: all
  conditions:
    - kind: compare
      field: event.arguments.file_path
      op: exists
    - kind: regex
      field: event.arguments.file_path
      pattern: '\.tsx?$'
      flags: i
    - kind: not
      condition:
        kind: regex
        field: event.arguments.file_path
        pattern: '\.d\.ts$'
        flags: i
```

| kind | 字段 | 语义 |
| --- | --- | --- |
| always | 无 | 成立 |
| all / any | conditions | 全部 / 任意子条件 |
| not | condition | 否定单个条件 |
| compare | field、op、value | 字段比较；exists 不带 value |
| regex | field、pattern、flags | 正则条件 |
| keywords | field、values、mode | 关键词条件 |
| count | source、pattern、metric、window、compare | 引擎计数条件 |
| extension | ref、revision、params | 已注册版本化条件扩展 |

通用树的深度最多 16，每个布尔组最多 64 项。动作依赖使用 `dependsOn: [动作ID]`，必须同阶段且无循环。事件选择、共同条件和接收者范围各自生效，不相互覆盖。

## 4. 自然请求与时间窗口

````markdown
> [!DSH-REMINDER] 晚间休息建议
>
> ```dsh-rule
> schemaVersion: 2
> id: evening-rest
> revision: 1
> on: [request.before]
> select: { view: original, roles: [user], blockTypes: [text] }
> event:
>   timeWindow: { start: '23:00', end: '03:00', timeZone: local }
>   humanActivity: { withinSeconds: 900 }
> match: { kind: always }
> actions:
>   - id: model
>     kind: notify
>     stage: request.before
>     enabledDefault: true
>     delivery:
>       model: { once: window }
> ```
>
> 现在已是深夜。如果没有紧急事务，可以商量一个合适的收尾点，休息一下。
````

跨午夜窗口归属开始日期。同一会话、来源、规则在同一窗口只消费一次；修改正文、压缩上下文和重启不重置已提交的窗口事实。真人在场来自 Host 记录，工具、插件和恢复历史不能伪造新的人类活动。投递前再次核对窗口及身份。

`reminder_snooze` 的空参数暂停当前会话正在生效的窗口提醒；指定 `sourceId` 和 `ruleId` 可只暂停一条，到窗口结束恢复。

## 5. 接收者与共享额度

顶层 `recipient` 筛接收会话，`match` 筛触发事实：

```yaml
recipient:
  sessionIds: [session-a, session-b]
  agentPresets: [writing]
  condition:
    kind: all
    conditions:
      - { kind: compare, field: session.agentPresetName, op: eq, value: 写作 }
      - { kind: compare, field: session.model, op: contains, value: gpt- }
```

列表内任意匹配，列表之间与条件树取交集，空列表无效。可用会话字段有 `sessionId`、`agentPreset`、`agentPresetName`、`provider`、`model`，均以 `session.` 开头。缺失身份不能满足比较，包括 `ne`；选择缺失可用 `not` 包裹 `exists`。

接收者条件支持 `all`、`any`、`not` 和 `compare`，每组 1–64 项，总计最多 128 节点，深度 16。比较支持 `eq`、`ne`、`contains`、`exists`；除 `exists` 外值为字符串。

动作的投递策略可让多个会话共享总次数：

```yaml
delivery:
  model:
    once: surface
    shared: { reset: lifetime, lifetime: project-launch-1, limit: 2 }
```

放在目标动作内。`lifetime` 是显式活动周期，正文或 revision 更新不重置次数；新活动更换它。窗口规则可用 `once: window` 和 `shared: { reset: window, limit: 1 }`，必须同时声明 `event.timeWindow`。共享额度在实际交付提交后消费，匹配本身不消费；未提交失败可释放预留。

## 6. 输出文本与工具错误

````markdown
> [!DSH-REMINDER] 核对完成证据
>
> ```dsh-rule
> schemaVersion: 2
> id: completion-evidence
> revision: 1
> on: [assistant.output]
> select: { view: original, roles: [assistant], blockTypes: [text, reasoning] }
> event:
>   blockTypes: [text, reasoning]
>   pattern: { kind: literal, text: 已全部完成 }
> match: { kind: always }
> actions:
>   - id: model
>     kind: notify
>     stage: assistant.output
>     enabledDefault: true
>     delivery:
>       model: { once: surface }
> ```
>
> 请核对验收条件与实际结果，再报告完成情况。
````

只检测供应商实际提供的文本或可读 reasoning。分片在单块内累积，不跨类型、块或 attempt 拼接。`pattern` 可为 `literal`、`keywords` 或 `regex`；正则模式使用 `regex` 字段，普通条件树则使用 `pattern` 字段。

默认保留每块最近 32768 字符，每 attempt 最多 64 块，队列最多 32 帧或 4 MiB。超限记录诊断，模型输出继续。需要显式取消并续接时，在动作的 `delivery.model` 中加 `interrupt: abort-resume`；Host 仍执行额度和持久化检查，默认每真人轮次最多中止一次。

工具超时只匹配结构化错误码：

````markdown
> [!DSH-REMINDER] 超时后核对
>
> ```dsh-rule
> schemaVersion: 2
> id: tool-timeout
> revision: 1
> on: [tool.failed]
> select: { view: original, roles: [tool], blockTypes: [tool-result] }
> event: { tool: pwsh, error: { code: TOOL_TIMEOUT } }
> match: { kind: always }
> actions:
>   - id: model
>     kind: notify
>     stage: tool.failed
>     enabledDefault: true
>     delivery:
>       model: { once: surface }
> ```
>
> 先核对命令是否仍在运行以及已发生的副作用，再决定如何继续。
````

普通非零退出不等于 `TOOL_TIMEOUT`。工具成功/失败选择和错误码由 Host 的原生执行事实提供。

## 7. 扩展与来源生命周期

条件扩展形如 `{ kind: extension, ref: package:condition, revision: 1, params: {...} }`，可嵌进布尔树。动作扩展还要声明 `id`、`stage`、`enabledDefault`，由引擎当前扩展目录编译为核心动作。实际外部执行由版本化执行器端口提供。卸载引用能力使对应计划和候选失效；无关扩展不会重置提醒事实。

连接建立和恢复时全量读取 callout，普通编辑按 WebSocket 的文档根 ID 增量读取。思源负责固定 SQL、flush、凭据和推送；引擎负责未变文档复用、失效合并、单条诊断、容量重试和来源撤回。空闲时不重复查询 SQL。`reminders.refreshMs` 默认 30000，只控制失败读取与容量候选重试。

总规则容量默认不限。降低容量保留已有规则，超限增长保留上一批；增加容量后重试缓存候选，不重复读思源。离线立即撤回来源，恢复后全量校准。

## 8. 排错

1. 核对原生块 type/subtype、callout 标记和唯一围栏。
2. 核对 Host 已加载提供 `reminderRules` 的 context-care `/requests` 行。
3. 核对会话的规则来源核心、核心连接状态和凭据。
4. 在会话规则目录看规则、动作和容量；单条语法或语义错误在来源日志中给出身份与字段诊断。
5. 确认 `on`、`stage`、`event.tool` 与真实工具完全一致，条件字段来自实际事件。
6. 核对当前身份、上下文去重、窗口与共享额度；已提交提醒不会因编辑正文而重放。

思源字段 `root_id`、事务 `rootIDs`、原生 callout 行属性都在 I/O 适配器处理。规则语法与执行能力以引擎公开契约为准，插件不另建解析或校验分支。
